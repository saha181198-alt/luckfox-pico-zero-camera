# Pico Zero: проверка прошивки и диагностика USB Host

Этот порядок предназначен для случая, когда Pico Zero уже работает в Host,
но подключение UVC-конвертера заканчивается `Cannot enable` и
`unable to enumerate USB device`. Сравниваются две сборки одного SDK:
обычная и с дополнительным журналированием USB. Проверка или замена кабеля
в этот порядок не входит.

`CONFIG_USB_DWC3_DUAL_ROLE=y` включает поддержку Host. Отсутствие отдельного
`CONFIG_USB_DWC3_HOST=y` при такой конфигурации само по себе не является
ошибкой. Регистрация `uvcvideo` тоже ещё не означает, что конвертер успешно
прошёл USB-перечисление.

## 1. Сохранить сведения о текущей системе через UART

В MobaXterm включите запись вывода текущей Serial-сессии в файл на ПК
(функция записи журнала терминала; название пункта зависит от версии).
Сохраните полный вывод следующих команд. Они только читают данные:

```sh
uname -a
cat /proc/cmdline
for p in model compatible; do
    printf '\nDevice Tree: %s\n' "$p"
    if [ -r "/proc/device-tree/$p" ]; then
        tr '\000' '\n' < "/proc/device-tree/$p"
    fi
done
cat /proc/partitions
if [ -d /dev/block/by-name ]; then
    ls -l /dev/block/by-name
fi
ls -l /dev/mmcblk*
if [ -r /sys/class/block/mmcblk0/size ]; then
    printf '\neMMC size, sectors of 512 bytes:\n'
    cat /sys/class/block/mmcblk0/size
fi
for p in /sys/class/block/mmcblk0p*; do
    [ -d "$p" ] || continue
    printf '\n%s: start and size, sectors of 512 bytes\n' "${p##*/}"
    cat "$p/start" "$p/size"
done
mount
if [ -r /proc/mtd ]; then
    cat /proc/mtd
fi
if [ -r /etc/camera-display.conf ]; then
    cat /etc/camera-display.conf
fi
if [ -r /proc/config.gz ]; then
    zcat /proc/config.gz
fi
dmesg
```

Сохраните журнал под именем `pico-before-reflash.txt`. Если исходный
`update.img` сохранился на ПК или в артефактах Actions, скопируйте его вместе
с контрольной суммой и сведениями о сборке в отдельную папку.

**Журнал, конфигурация ядра и копия настроек не являются резервной копией
прошивки.** Даже исходный `update.img` не сохраняет изменения и пользовательские
данные, внесённые на плате после его записи.

## 2. Подготовить восстановимую резервную копию

При доступе только через UART и USB к ПК полную копию eMMC следует снимать
средством чтения памяти Rockchip на ПК, если выбранная версия программы и
режим устройства поддерживают такую операцию для RV1106. Наличие кнопки
прошивки в SocToolKit не доказывает наличие функции чтения обратно.

Для выбора точной процедуры нужны:

- вывод инвентаризации из предыдущего раздела;
- название и версия установленной на ПК программы Rockchip, а также её
  доступные функции чтения памяти или резервного копирования.

Пока эти сведения не получены, команда снятия полной копии не определена.
Не используйте случайные смещения разделов из инструкций для других плат.
Чтение нужных областей, их размеры, сохранение таблицы разделов и способ
обратной записи должны быть согласованы с фактической разметкой; если
используются отдельные загрузочные области eMMC, их также нужно учесть.
Сохраните файлы копии на ПК, проверьте ожидаемые размеры и контрольные суммы.
Контрольная сумма проверяет сохранность файла, но сама по себе не подтверждает
полноту резервной копии и возможность загрузки после восстановления.

До определения способа восстановления текущей системы не переходите к
`Upgrade`, `Erase` или записи разделов. Подготовку новых образов можно
выполнять независимо от этого шага.

## 3. Подготовить две сравнимые сборки

Используйте одну ревизию этого проекта и SDK
`824b817f889c2cbff1d48fcdb18ab494a68f69d1` для обеих сборок. Это известная
база проекта на официальном SDK, а не неизменённый официальный образ:
проект добавляет USB Host, ST7735 и средства работы с камерой.

В GitHub Actions запустите workflow **Build Pico Zero UVC to ST7735 firmware**
дважды из одной ревизии проекта. Сохраните значение `sdk_ref` по умолчанию,
выберите `artifact_set: update-only`; для первого запуска оставьте
`usb_debug` выключенным, для второго включите его. Скачайте артефакты обоих
успешных запусков в разные папки и сохраните ссылки на запуски.

Push изменений сборки в ветку `codex/usb-host-diagnostics` автоматически
запускает оба профиля одной ревизии. Обычный push в `main` собирает один
обычный профиль; ручной запуск в любой ветке использует выбор `usb_debug`.
Артефакты имеют суффикс `normal` или `usb-debug` и номер запуска. В них
входят `update.img`, `kernel.config`, `pico-camera-build-info.txt`, ревизии
SDK/проекта, журнал и `SHA256SUMS.txt`. Диагностическая сборка не публикуется
как успешная, если в итоговом `.config` нет нужных драйверов, dynamic debug
и событий трассировки.

Для локальной сборки в Ubuntu 22.04 с зависимостями и запасом диска из [README_RU.md](../README_RU.md#7-локальная-сборка)
запустите из корня проекта:

```bash
USB_DEBUG=0 bash scripts/build-local.sh "$PWD/luckfox-sdk-normal"
USB_DEBUG=1 bash scripts/build-local.sh "$PWD/luckfox-sdk-usb-debug"
```

Отдельные каталоги SDK исключают перенос результатов предыдущей сборки
между профилями. Полные образы появляются в `output/image/update.img`
соответствующего SDK только после успешной сборки. Сохраните оба образа
и их контрольные суммы, явно указав профиль в названии папки на ПК.

Сначала проверьте обычную сборку. Если на ней сохраняется сбой, переходите
к диагностической. Между проверками сохраняйте прежнее подключение,
питание и порядок включения. Диагностическое журналирование может влиять
на задержки, поэтому результат обеих сборок имеет значение.

После загрузки каждого нового образа сохраните через UART:

```sh
cat /etc/pico-camera-build-info
uname -a
grep -q ' /sys/kernel/debug debugfs ' /proc/mounts || mount -t debugfs debugfs /sys/kernel/debug
usb-host-diagnostics collect > /tmp/usb-host-before.txt
cat /tmp/usb-host-before.txt
```

Файл `/etc/pico-camera-build-info` позволяет сопоставить результат с ревизиями
SDK и проекта и выбранным профилем. На старой прошивке этого файла и новой
утилиты может не быть.

## 4. Снять отчёт на диагностической сборке

Оставьте запись UART-сессии в MobaXterm включённой. Выполните:

```sh
usb-host-diagnostics enable
```

Воспроизведите одно подключение конвертера тем же способом, которым получали
ошибку ранее. После появления результата сохраните отчёт и выключите
дополнительное журналирование:

```sh
usb-host-diagnostics collect > /tmp/usb-host-after.txt
usb-host-diagnostics disable
cat /tmp/usb-host-after.txt
```

Не оставляйте подробное журналирование включённым на время обычной работы.
Сохраните получившийся журнал на ПК вместе с данными сборки. Файлы в `/tmp`
не заменяют сохранение на ПК: они могут исчезнуть после перезагрузки.

Успешное определение означает появление устройства конвертера в `lsusb`,
а затем привязку `uvcvideo` и создание соответствующего `/dev/video*`.
Для известного конвертера ожидается USB ID `1a86:8095`.
Если снова видны только корневые хабы, исследовать нужно журнал USB reset,
состояние xHCI и PHY. Настройка разрешения, OpenCV и FFmpeg начинается после
успешного определения устройства.

Рецепты CSI-камер и режима UVC Gadget решают другие задачи.
`usb_config.sh` и `rk_mpi_uvc` для этой проверки запускать не нужно: Pico
должен оставаться USB Host для внешнего конвертера.

Эта процедура не подтверждает исправность новой прошивки на физической
плате. Итог сборки, возможность восстановления и результат USB-подключения
проверяются отдельно.
