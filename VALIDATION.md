# Проверка комплекта

## USB Host diagnostics — 2026-10-13

В облачной среде проверены:

- `actionlint` 1.7.7 для workflow с обычным/диагностическим профилями;
- `scripts/verify-project.sh`, синтаксис shell и `git diff --check`;
- применение фактического SDK-патча к копии файлов закреплённой ревизии,
  последовательность профилей `0 → 1 → 1 → 0`, отсутствие накопления debug
  настроек, сведения о сборке, права исполнения и отказ при неверном профиле;
- компиляция Device Tree и свойства Host/ST7735, три цепочки FFmpeg;
- диагностическая утилита на временной модели файловой системы: сбор без
  изменений, включение/выключение только выбранных dynamic-debug сообщений,
  отказ при отсутствии нужных точек журналирования;
- проверка итогового Kconfig на явно обозначенных тестовых конфигурациях:
  принимаются Host/Dual Role, отклоняются неполные конфигурации и сырой фрагмент.

Это проверки подготовки сборки и инструментов. Полная ARM-компиляция,
настоящий результат `olddefconfig`, готовый `update.img` и работа USB на плате
на этом этапе не подтверждены. CI дополнительно проверяет фактический
`sysdrv/source/objs_kernel/.config` после сборки SDK перед упаковкой образа.

## Исходная проверка комплекта

Дата проверки: 2026-09-03.

Проверено относительно официального Luckfox Pico SDK commit
`824b817f889c2cbff1d48fcdb18ab494a68f69d1`:

- патч корректно разбирается Git и чисто применяется к указанному commit;
- SDK выбирает только board config
  `BoardConfig-EMMC-Buildroot-RV1106_Luckfox_Pico_Zero-IPC.mk`;
- SDK принимает дополнительный kernel fragment
  `rv1106-camera-st7735.config`;
- итоговый Device Tree компилируется в DTB;
- в скомпилированном DTB подтверждены USB Host, SPI0 CS0, отключённый
  `spidev@0`, `sitronix,st7735r`, 32 МГц, поворот 90°, GPIO1_D2 и GPIO1_D3;
- все добавленные shell-скрипты проходят синтаксическую проверку;
- GitHub Actions YAML корректно разбирается YAML-парсером;
- FFmpeg принимает цепочку масштабирования, обрезки, ограничения FPS и
  преобразования в `rgb565le`;
- запрошенные опции FFmpeg существуют в поставляемом Buildroot 2023.02.6.

При проверке Device Tree остаются предупреждения в штатных узлах SDK
(`rkisp-vir0` и `clocks`). Добавленный узел ST7735 новых предупреждений не
создаёт.

## Что можно проверить только на плате

В этой среде не выполнялась многочасовая полная сборка SDK и нет физического
Pico Zero, конкретного TFT и UVC-конвертера. Поэтому после первого запуска
нужно подтвердить:

- электрическое питание VBUS выбранного OTG-Y/USB-hub;
- поддерживаемый UVC-режим конвертера;
- порядок цветов конкретной партии TFT (`bgr;`);
- направление изображения (`rotate = <90>` или `<270>`);
- устойчивость проводов на 32 МГц; при помехах используйте 16 МГц.

Диагностические команды и исправления для каждого случая приведены в
`README_RU.md`.
